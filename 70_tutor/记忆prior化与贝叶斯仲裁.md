# 记忆 prior 化与贝叶斯仲裁：多记忆源冲突怎么办

## 概念
带记忆的 agent 迟早遇到：共享库说 A、用户自己的记录说 B。成熟做法**不设记忆间硬优先级**，而是三层：
1. 矛盾必须**双源分标**摆出来（"共享库认为 X / 你的复盘认为 Y"），禁止和稀泥合并成"市场有分歧"；
2. 双方都只是 **prior**——尤其"模型自己曾写入的综合 insight 不得原样当当前事实"；
3. 引第三方**当下数据**（行情/财报/新闻）做三角验证，输出"当前数据更支持 Z（理由）+ 监控信号"。
唯一硬规则留给事实层：记忆 vs 数据源冲突，以数据源为准（数字类）。

## 为什么
这是贝叶斯姿态：记忆=先验、数据=似然，先验冲突不该内部裁决，该用新证据更新。更关键的是第 2 条防住 **RAG 自我强化回路**——模型把自己昨天生成的结论检索回来当"事实"，错误会复利式放大（类比：模型在自己生成的数据上训练导致的 model collapse）。

## 实现对照
- Knevo：上述三层 + "共享框架优先级不低于用户记忆"（防个人偏见，措辞是不低于非高于）（q11）。
- 我们缺的门：workbench 检索到旧 synthesis 结论目前直接引用，未标"历史基线"也未强制盘面数据核验——回灌第一梯队。

## 跨域同构
分布式系统的冲突解决（不靠时间戳硬裁决、靠 quorum 读修复）；审计里的三角验证（triangulation）。
