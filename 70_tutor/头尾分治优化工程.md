# 头部/尾部优化工程清单

> 头部目标：更省、更稳。尾部目标：能力上限 + 不出重大错。

## 头部（高频、可预期）
1. **缓存分层**：精确缓存 → 语义缓存（嵌入相似即复用，GPTCache 思路）→ **中间结果缓存/预计算物化**（最实用；我们的 mention_frequency.json、dashboard 预构建即此，查询时零 LLM 成本）
2. **降模型**：高频固定任务用小模型/纯规则替代大模型（matcher 用精确匹配 = 降到零模型）
3. **模板化输出**：LLM 只填槽（JSON 字段），渲染交给模板引擎——省 token 且格式零漂移
4. **批处理与错峰**：非实时任务攒批跑（batch API 常半价）
5. **prompt 瘦身**：高频路径每省 100 token × 调用量 = 真钱

## 尾部（低频、五花八门）
1. **出口 verifier 分级**：按风险分级质检——写库/交易判断过硬闸门，闲聊轻检或免检
2. **检索前置（prime）**：兜底前强制先查库再答，杜绝"没查就编"
3. **表达契约**：给自由编排划红线（禁数值概率、缺数说缺数）——少量约束换大幅降低离谱输出，比全量质检便宜
4. **尾部→头部晋升管道**（最重要的闭环）：统计尾部问题日志，某类反复出现就沉淀成新 skill/模板。"问题资产管理"是人肉版，工程化 = 查询日志聚类分析
5. **failure 库**：尾部出过的错记进 lessons/corrections，注入后续兜底上下文

## 一句话
头部优化 = **把 LLM 从路径里往外挤**（能不推理就不推理）；尾部优化 = **给 LLM 套护栏而不是套流程**；中间靠晋升管道让系统越用越省。
