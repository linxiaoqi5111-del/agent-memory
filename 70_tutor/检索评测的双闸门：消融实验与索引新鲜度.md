# 检索评测的双闸门：消融实验与索引新鲜度

## 一句话先懂

消融实验判断“哪个模块有贡献”，索引新鲜度门禁判断“这次实验是否有资格形成当前结论”；两道门都通过，指标才可能指导上线。

## 大白话解释

把知识库想成一个仓库，我们在比较几种不同的找货方法。

先拿模拟订单演练，可以确认员工会走、路线接得上、结果能记录。这叫 `smoke test（冒烟测试）`：它主要证明整条管线没有明显故障，不负责证明真实营业时一定找得最准。

接着，我们每次只替换一种找货方法，比较关键词、语义、混合检索、图关系扩展和重排序各自带来的变化。这叫 `ablation（消融实验）`：它像逐个更换轮胎、发动机或导航，目的是弄清楚性能变化来自哪个部件，而不是只看整车最终快了多少。

但比赛还必须使用当前库存表。仓库现在有九万件货，如果评测仍拿只登记了六万件的旧表，即使某种方法赢了一点，也不能宣布它是正式冠军。`freshness gate（新鲜度门禁）` 就是赛前核对“评测索引”和“当前知识库”是否来自同一个快照；对不上就阻止正式结论。

所以，“管线跑通”“出现初步信号”“正式证明有效”是三个不同等级，不能混着说。

## 技术映射

检索评测至少要分开检查三件事：

1. **实现有效性**：各检索模式能否运行，结果结构、解释路径和错误门禁是否正确；
2. **实验有效性**：索引、查询集和真值是否对应当前版本，比较时是否只改变目标变量；
3. **业务有效性**：真实用户问题上的召回、排序和证据质量是否真的改善。

常见的检索消融可以写成：

```text
BM25 关键词检索
→ dense 向量检索
→ hybrid 混合检索
→ wikilink 双链扩展
→ typed graph 带类型图扩展
→ rerank 重排序
```

每增加一层，都应与前一层使用相同查询、相同真值和相同知识快照比较。否则指标变化可能来自数据变化，而不是模块本身。

索引新鲜度可以用内容快照实现：为当前知识块计算稳定摘要，并与建索引时保存的摘要比较。只要两者不一致，正式评测就失败关闭；需要排障时可以显式允许陈旧索引，但产物必须标为非正式。

## 术语对照

- `Ablation（消融实验）`：一次移除、替换或增加一个组件，通过对照确定它的独立贡献。
- `freshness gate（新鲜度门禁）`：检查索引等派生产物是否与当前源数据同步，不同步时阻止正式结论。
- `smoke test（冒烟测试）`：快速验证系统主路径能否运行的低成本测试，不等于完整质量验证。
- `BM25（经典关键词相关性算法）`：根据词频和词的稀有程度给文档排序。
- `dense retrieval（稠密向量检索）`：把查询和文本编码成向量，根据语义距离召回。
- `hybrid retrieval（混合检索）`：组合关键词与向量检索，兼顾精确词面和语义相似。
- `typed graph（带类型图）`：图中的边不仅表示“有关联”，还记录供应、隶属、暴露等关系语义。
- `rerank（重排序）`：先召回候选，再用更精细但更昂贵的模型重新排序。
- `BGE（智源研究院开源的文本向量与重排模型系列）`：可用于生产级语义召回和重排序评测。

## 本轮场景对照

P4 先用确定性的 hash smoke（哈希冒烟测试）跑通六种检索模式、带证据的 typed graph 和可解释路径。结果显示图扩展有初步正向信号，但哈希方法不是生产语义模型，因此不能把这次结果写成正式收益。

正式结论还需要：

1. 用当前知识库完整重建 BGE 索引；
2. 通过索引新鲜度检查；
3. 在同一批真实查询和真值上重跑各模式；
4. 同时检查指标变化与具体案例，避免平均数掩盖错误扩展。

## 边界与反例

- 索引新鲜只说明“用的是当前数据”，不说明数据内容正确、真值可信或模型效果好。
- 消融实验能帮助归因，但组件之间可能有交互；单模块有效，不代表组合后一定继续有效。
- 指标小幅上升不自动等于业务收益，还要检查样本量、失败案例、延迟和成本。
- 冒烟测试不是“没价值的假测试”。它适合低成本发现接线、数据结构和门禁错误，只是不承担最终效果证明。
- 正式模型也不自动产生正式结论；如果索引陈旧、查询不真实或真值错误，昂贵模型只会让无效实验更昂贵。

## 可复用检查清单

1. 这次实验是在证明“能运行”，还是证明“效果更好”？
2. 索引、查询和真值是否来自同一时间点和版本？
3. 对照组之间是否只改变了一个目标变量？
4. 指标提升是否同时有具体案例和证据路径支持？
5. 是否把冒烟结果、离线结果和生产结果清楚分级？
6. 新方案的延迟、成本和错误扩展是否也在验收范围内？

## 自测题

某导航算法在去年的旧地图上比旧算法快 2%，最严谨的结论是什么？

## 跨领域同构

- **导航系统**：旧地图上的速度提升不能直接代表当前道路表现。
- **仓储系统**：过期库存表会让更快的找货算法得到失真的评测。
- **推荐系统**：旧用户行为训练出的离线提升，需要用当前流量继续验证。
- **医学试验**：实验组与对照组若同时改变治疗方案和入组人群，就无法判断疗效来自哪里。
- **软件性能测试**：更换算法时若同时升级机器，速度提升就不能全部归因于算法。
