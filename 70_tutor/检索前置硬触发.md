# 检索前置硬触发：给兜底质量设下限

## 概念
"先检索、后开口"不靠模型自觉，而是写成**条件触发表**：消息命中某类词面/语义（具体标的、"最近/今天"、财报词、用户表态观点），就强制调用对应检索工具，且**记忆+行情+新闻并行齐发**（禁串行）；空结果做 query rewriting（简称↔全称/中英/名↔代码，≤3 次）后仍空则如实报缺；只有寒暄/流程澄清/纯静态概念三条豁免。

## 为什么
兜底（无 skill 命中的自由回答）最容易"没查就编"。出口 verifier 只能兜住上限，**质量下限要靠检索前置**——两端夹逼。触发表用"词面+语义混合"比纯触发词鲁棒、比纯 LLM 判断可审计。

## 亮点设计
- "快答 = 检索后短答"，不等于跳过检索。
- **用户给出观点/持仓也是触发条件**：用户一表态就拉历史基线核验（先核验再回应，与我们事后 record-correction 互为对偶）。
- 空结果也是信息，必须披露，禁止以"可能没覆盖"为由跳过。

## 跨域同构
数据库查询前的强制索引检查；客服机器人"先查工单再回复"；query rewriting 是搜索引擎同义改写的老技术（面试常考：召回率优化手段）。
