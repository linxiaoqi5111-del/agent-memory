# 金融 Agent 问答经验卡片机制

## 核心原则

金融 agent 的经验沉淀不要直接混进事实知识库。事实库回答“世界发生了什么”，经验卡片回答“下次应该怎么想”。两者混在一起会污染 RAG 检索，让模型把方法论当公司事实。

## 当前分层

- 金融 repo：机器可读学习层，`intelligence/users/<user>/experience_cards.jsonl`，记录问题、回答得分、扣分维度、修正原则、下次提示规则。
- `agent-memory`：人类可读长期方法论层，存放被确认、可跨 agent 复用的原则。
- 知识库 repo：事实证据层，只放公司、产业、公告、互动易、年报、研报等证据。
- eval cases：回归测试层，把典型问题变成可重复打分样本。

## 最小闭环

1. Agent 正常回答。
2. 用 `answer-score` 打分。
3. 对低分或高价值回答加 `--save-card`，生成经验卡片。
4. 下次 `ask/chat --compose --user <id>` 读取相关经验卡片，注入合成提示。
5. 多次验证有效的卡片升级到 `intelligence/foresight_methodology.md` 或本 vault 方法论笔记。

## 关键样例

2026-06-29 的“科技细分哪个方向还有上涨空间”回答得分 59/100。卡片沉淀的修正原则：

> 泛方向判断不能只给排序，必须先定市场阶段，再看资金容量、双红、扩散和生命周期位置；随后拆 L1-L4 证据，补产业链到财务科目的映射，最后给反方审稿与证伪条件。

下次提示规则：

> 回答科技/题材上涨空间问题时，不得只给方向排序；必须覆盖市场阶段、资金容量、双红/扩散、L1-L4 证据分层、产业链到订单/收入/毛利率映射、反方审稿、后续验证和证伪条件。

## 可复用知识

JSONL 适合做早期学习样本：追加安全、便于审计、可手工删除坏样本。等样本量变大后，再引入 BM25/向量混合检索和 rerank。
