# 数据 ingest 重复任务

ingest（抓取 / 入库）是高频、机械、可复现的活。**沉淀的对象是"流程"，不是"每次的流水账"。** 流程写一次（本文件）；每次执行默认**不写交接**，只在"这次和上次不一样"时补一两行。

## 核心原则
> 交接的价值 = 下次能省多少重复思考。机械、可复现、无决策的执行不必逐次交接；该固化的是可复跑的流程。

## 一、流程固化（写一次，仅在流程变化时更新）
把每条 ingest 流水线在下表登记一次。**新增/变更数据源或清洗规则时才改这里。**

| 流水线 | 数据源 | 入口命令 | 落库位置 | 字段/清洗要点 | 已知坑 |
|---|---|---|---|---|---|
| 示例：行情日线 | xxx API | `python -m fwp.ingest.daily` | `data/daily.duckdb` | 去重按 (code,date)；时区 UTC | API 限流 5 req/s |
| … | | | | | |

> 填表后，下次（或交给 Devin）照着跑即可，无需口头交接。

## 二、每次执行：默认不写交接
一次**正常成功**的 ingest（数据进库、数量对、无报错）→ **不写交接、直接结束**。

只有命中下面任一"异常信号"时，才在 `20_projects/<repo>.md` 的「交接记录」补一两行：
- 数据源 / 接口变了（字段改名、API 限流、格式变化）
- 这次踩了新坑或加了新清洗规则 → **顺手更新上面第一节的表**
- 数据有异常需下次注意（缺某段时间、口径变了、数量异常）
- 跑了一半失败、留了中间状态需要交接

交接行格式（同 devin-writeback）：
`YYYY-MM-DD · <agent> · ingest <流水线>：<异常/变更一句话>`

## 三、和 Stop 门禁的关系（纯数据改动豁免）
`.claude/hooks/check-writeback.sh` 已加**纯数据改动豁免**：当本次改动**只**涉及数据产物（`data/`、`*.parquet`/`*.duckdb`/`*.db`/`*.csv`/`*.jsonl`/`*.arrow` 等）而**没动代码**时，结束直接放行、不要求写交接。
- 因此机械 ingest 一般不会被门禁打扰；
- 一旦改了代码（脚本、清洗逻辑），门禁照常要求回写——因为那才是有决策价值的改动。

## 红线
- ingest 的原始大文件 / 数据库（`*.duckdb`/`*.parquet` 等）**不要提交进 git**（pre-commit 已硬拦）；落本地数据目录或对象存储。
- 不写任何密钥 / token 到 vault 或代码。

## 失败/回退
- 跑失败 → 在交接记录写明失败点、已落的中间状态、下一步，不要假装成功。
- 数据源彻底变更 → 更新第一节的表 + 在 `10_knowledge/` 留一条"为什么这么改"。
